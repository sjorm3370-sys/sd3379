# 오늘의 보드 · Supabase 저장 버전

원본 단일 HTML의 화면과 주요 기능을 유지하며 HTML/CSS/JavaScript를 분리했습니다. 서버 설정 전에는 동작하지 않습니다. 기존 Vercel/Supabase 계정에 접속하거나 실제 배포를 변경한 결과물은 아닙니다.

## 설치 및 기존 Vercel 서비스 적용

1. Supabase 프로젝트를 준비하고 SQL Editor에서 `supabase.sql`을 실행합니다. 신규 테이블용 스크립트이므로 기존 `public.tasks`가 있다면 충돌 여부를 확인하고 별도 마이그레이션하세요. 반복 실행용이 아닙니다.
2. 프로젝트의 API 설정에서 Project URL과 **publishable key 또는 anon public key**를 확인합니다. `config.js`의 두 값을 교체합니다. **service_role/secret 키는 사용하지 마세요.**
3. Supabase Auth에서 이메일/비밀번호 로그인을 사용하도록 설정합니다. Authentication의 URL Configuration에 실제 Vercel 주소를 Site URL로 설정합니다. 이메일 인증 후 돌아올 주소도 실제 사용 도메인으로 허용합니다. 운영 환경에서는 이메일 인증을 유지하는 것을 권장합니다.
4. 기존 Vercel에 연결된 저장소의 정적 사이트 루트에 이 폴더 **안의 파일들**을 반영합니다. 기존 파일 구조가 다른 경우 Root Directory를 맞춥니다. 원본은 먼저 별도 보관하세요.
5. 정적 사이트 기준 Framework Preset은 Other, Build Command는 비우고, Output Directory는 현재 정적 루트(`.`)로 설정합니다. 불필요한 기존 빌드 명령이 남아 있지 않은지 확인하고 커밋/푸시하여 재배포합니다.
6. 배포된 HTTPS 주소에서 회원가입 → 인증 메일 확인 → 로그인을 진행합니다. 이메일 확인 설정에 따라 회원가입 직후 로그인되거나 확인 메일이 전송됩니다.

별도 패키지 설치, npm 빌드, Vercel 서버 함수는 필요 없습니다. 이 버전은 `config.js`를 직접 읽습니다. Vercel 대시보드에 환경변수를 등록하기만 해서는 정적 JS 값이 바뀌지 않습니다. 공개 키만 이 파일에 입력하세요.

## 기존 브라우저 카드 옮기기

1. 기존 페이지를 사용하던 **동일 브라우저/동일 배포 주소**에서 먼저 ‘백업 내보내기’를 실행합니다. 재배포 전에 진행하세요.
2. 새 버전을 배포하고 로그인합니다.
3. ‘백업 가져오기’로 JSON 파일을 선택합니다.
4. 현재 로그인 계정의 카드가 백업으로 **전부 교체**됩니다. 이미 카드가 있다면 먼저 백업하세요.
5. 다른 브라우저에서도 같은 계정으로 로그인하여 데이터가 보이는지 확인합니다.

원본 `personal-kanban-v1` localStorage 데이터는 자동 이관하지 않으며, 새 코드는 기존 브라우저 저장소를 읽거나 쓰지 않습니다. 백업을 미리 확보하지 못했다면 원본 파일을 동일 출처에 다시 제공하여 기존 내보내기 기능으로 백업을 확보해야 합니다. 출처가 달라지면 해당 브라우저 저장소도 달라집니다.

## 기능

- 카드 생성·수정·삭제, 우선순위 변경, 완료/취소, 열 사이 드래그 이동을 DB에 저장
- 제목/내용 검색, 진행률, 카드 수 표시
- 로그인 사용자별 개인 보드, RLS로 계정 간 접근 차단
- 원본 version:1 JSON 백업 호환, 원자적 전체 교체
- 인증 토큰도 메모리 보관: 페이지를 새로 열거나 브라우저 새로고침하면 재로그인
- 다른 기기의 변경사항은 화면의 ‘새로고침’ 버튼으로 반영

## 검증 체크리스트

- [ ] 회원가입, 메일 인증, 로그인 성공
- [ ] 카드 추가 후 Supabase Table Editor에 행 생성
- [ ] 수정/우선순위/완료/드래그 후 DB 값 변경
- [ ] 브라우저 새로고침 후 재로그인해 동일 카드 확인
- [ ] 다른 브라우저에서 같은 계정의 카드 확인
- [ ] 다른 계정으로 로그인 시 카드 미노출
- [ ] 다른 계정 JWT로 REST 조회/수정해도 타인 카드 접근 불가
- [ ] 삭제 후 DB 행 제거
- [ ] 백업 가져오기 성공, 실패 시 기존 DB 카드 유지
- [ ] 네트워크 차단 시 오류 안내, 저장 성공 메시지가 나타나지 않음

## 확인 범위

제공 코드에 대해 JavaScript 구문 검사, HTML/CSS/JS 분리, 브라우저 저장 API 미사용, 필수 DOM ID 및 원본 주요 기능 연결을 정적으로 확인했습니다. 실제 Supabase 자격정보와 배포 권한이 제공되지 않아 실제 로그인·DB 쓰기·RLS 통합 테스트 및 Vercel 배포 검증은 수행하지 않았습니다. 위 체크리스트를 실제 프로젝트에 연결한 후 진행하세요.

오류 시 우선 SQL 실행 여부, URL/공개 키, Auth 설정과 인증 메일, RLS 정책, 네트워크 응답을 확인하세요. 개발자 도구나 화면 캡처를 공유할 때 JWT/비밀번호 등은 가리세요.
